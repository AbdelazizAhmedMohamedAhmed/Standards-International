# Website audit and improvement backlog

Reviewed 6 November 2026. Goal: support buyer sourcing requests and manufacturer/export partner inquiries equally.

This is a scoped source, dependency, and local-production-browser audit, not a guarantee that every defect has been found. The live Hostinger deployment, DNS, mailboxes and TLS could not be independently inspected because the environment cannot access the public domain or Hostinger connection. Local browser checks use system fallback fonts because Google Fonts access is unavailable under the environment network policy. No live inquiries were sent.

## Verification record

- Existing baseline: 11 local routes checked, unknown routes returned 404, no browser runtime errors, no broken images, four representative templates scanned with axe.
- Before/after: mobile menu expanded state missing → present; empty-form focus stayed on button → moves to name field; reduced-motion entrance animation/smooth scrolling active → disabled; serious contrast findings → no A/AA findings in scanned templates.
- Seven Vitest tests; TypeScript check, lint and production build pass. Lint retains six warnings.
- All eight main pages checked at 360, 390, 768 and 1440 pixels: one H1 per page, no horizontal overflow and shared social image present. Keyboard menu handling, buyer/partner navigation, both valid checklists and oversized-attachment validation passed.
- Supplied services video played in Chromium and sought successfully after buffering; no browser runtime errors were observed. This does not establish efficient streaming on the live host.
- Title-case “Standards” browser titles, transparent enlarged favicon and fallback ICO were checked in the final production output.
- Frozen Bun lockfile install is required. Dependency audit still intentionally reports the single moderate lint-tool advisory described above; it is not a clean audit result.
- Added HTTP headers checked on real local production responses for home, contact, services, robots and sitemap.
- Browser audit reports/screenshots are retained in /workspace outside the repository. Live deployment, DNS, TLS, mailbox delivery and hosted CI remain unverified until independently checked.
